# Scope and contract decisions

The independently approved plan implements issue #14 after the decision release. The user authorized reviewed planning, implementation, main commits, pushes, deployment verification and closing completed issues with solution comments.

Catalog responses expose `id`, `name`, `instructions`, `tone`, `operatingConstraints`, `revision`, `builtIn`, `createdAt` and `updatedAt`. POST and PUT return the full authoritative persona. DELETE returns 204. Conflict responses use `{ error: string }`; the client retains its draft and expected revision until explicit reload. IDs are generated by the server. `default` is immutable and adds no prompt text.

Workflow JSON adds `defaultPersonaId`, per-step `personaId` and server-resolved `personaSnapshot`. Null task selection inherits; explicit `default` opts out. Only Plan, Implement and AddressComments support selection. Version creation returns the enriched document and resolves each referenced catalog ID once. Pinned execution never consults mutable catalog rows.

The editor must not mark changes made during an asynchronous save as saved. Capture the submitted draft, derive its authoritative baseline from the returned version, and preserve later edits as dirty. Server snapshot metadata should not silently overwrite later selection or graph changes. Add a delayed-save regression.
